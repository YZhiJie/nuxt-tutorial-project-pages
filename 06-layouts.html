06. 布局系统与页面过渡 ​

本章示例：app/layouts/default.vue、app/layouts/blank.vue、app/pages/login.vue、app/app.vue 运行方式：cd app && npm install && npm run dev，访问 http://localhost:3000/login 体验布局切换与页面过渡

概念解析 ​

布局是包裹在页面外面的「壳」。Nuxt 4 约定 app/layouts/ 目录下的 .vue 文件即布局：default.vue 是默认布局，所有未显式指定布局的页面都会被它包裹；布局内部必须有一个 <slot /> 作为页面出口，否则页面内容不会渲染。多布局场景只需新增文件（如 blank.vue），页面通过 definePageMeta({ layout: 'blank' }) 声明使用哪个布局。

app.vue 中的标准组合是 <NuxtLayout> 套 <NuxtPage>：NuxtLayout 根据当前页面的 meta 渲染对应布局，NuxtPage 渲染页面本体。若需要在运行期动态切换布局（例如按用户角色在 admin / default 之间切换），可以给 NuxtLayout 传 :name 属性，它的优先级高于页面 meta 中的声明。

页面过渡基于 Vue 的 <Transition>，Nuxt 在页面切换时自动为 NuxtPage 套上过场。开启方式有两种：全局在 nuxt.config.ts 写 app: { pageTransition: { name: 'page', mode: 'out-in' } }，或单页在 definePageMeta 里写 pageTransition；然后按 name 提供 .page-enter-from 等 CSS 类即可。mode: 'out-in' 表示旧页面先离场、新页面再进场，能避免两个页面同屏造成的布局抖动。布局切换的过渡同理，配置项是 layoutTransition（默认 name 为 layout）。

过渡是否触发，取决于 NuxtPage 的 page-key：key 变化 → 旧组件卸载、新组件挂载 → 过渡发生。默认 key 与路由记录相关，因此 /notes/1 跳到 /notes/2（同一条路由记录、仅参数变化）默认不触发过渡；把 :page-key 绑定为 (route) => route.fullPath 即可让参数、查询变化也触发重建与过渡。与之相对的优化是 keepalive：让符合条件的页面组件切走后保留实例，返回时原样恢复（长表单、多标签页常用）。

典型应用场景 ​

  • 统一站点外壳：default.vue 组合 AppHeader / 页面出口 / AppFooter，全站共享导航与页脚。
  • 沉浸式页面：登录页、营销落地页使用 blank.vue，不被站点外壳干扰。
  • 动态布局：依据用户角色或实验分组，用 <NuxtLayout :name="..."> 在运行期切换布局。
  • 转场动效：列表 → 详情、步骤流页面用 pageTransition 提升质感与方向感。
  • 状态保活：多标签页或长表单页用 keepalive 缓存，返回时不丢失输入与滚动位置。

完整代码示例 ​

vue
<!-- 文件: app/layouts/default.vue -->
<template>
    <div class="layout-default">
        <AppHeader>
            <!-- 默认插槽：主导航链接 -->
            <NuxtLink to="/notes">笔记</NuxtLink>
            <NuxtLink to="/playground">练习场</NuxtLink>
            <!-- 具名插槽：页头右侧操作区 -->
            <template #actions>
                <NuxtLink to="/login">登录</NuxtLink>
            </template>
        </AppHeader>
        <main class="container">
            <!-- 页面出口：必须有，否则页面内容不渲染 -->
            <slot />
        </main>
        <AppFooter />
    </div>
</template>

运行方式：cd app && npm install && npm run dev，访问 http://localhost:3000/ 即可看到「页头 + 内容 + 页脚」的默认布局。

vue
<!-- 文件: app/layouts/blank.vue -->
<template>
    <!-- 空白布局：只保留页面出口，用于登录页等沉浸式场景 -->
    <slot />
</template>

运行方式：访问 http://localhost:3000/login ，该页声明了使用 blank 布局，看不到页头页脚。

vue
<!-- 文件: app/pages/login.vue -->
<script setup lang="ts">
    // 声明本页使用 blank 布局，并单独配置页面过渡
    definePageMeta({
        layout: 'blank',
        pageTransition: { name: 'slide', mode: 'out-in' }
    })
</script>

<template>
    <main class="login-page">
        <h1>登录 Nuxt LearnHub</h1>
        <!-- 表单与 $fetch 提交逻辑见第 08 章 -->
    </main>
</template>

运行方式：从首页点击「登录」进入 http://localhost:3000/login ，可观察到 slide 过渡（CSS 类定义在 app.vue 中）。

vue
<!-- 文件: app/app.vue -->
<template>
    <NuxtLayout>
        <!-- page-key 按完整路径生成：参数/query 变化也会重建页面并触发过渡 -->
        <!-- keepalive：最多缓存 5 个页面实例，返回时保留滚动位置与输入 -->
        <NuxtPage :page-key="(route) => route.fullPath" :keepalive="{ max: 5 }" />
    </NuxtLayout>
</template>

<style>
    /* 全局页面过渡：对应 pageTransition.name = 'page'（在 nuxt.config 的 app.pageTransition 中开启） */
    .page-enter-active,
    .page-leave-active {
        transition: opacity 0.2s ease, transform 0.2s ease;
    }
    .page-enter-from,
    .page-leave-to {
        opacity: 0;
        transform: translateY(8px);
    }

    /* 登录页自定义过渡：对应 definePageMeta 中的 name = 'slide' */
    .slide-enter-active,
    .slide-leave-active {
        transition: transform 0.25s ease, opacity 0.25s ease;
    }
    .slide-enter-from {
        transform: translateX(24px);
        opacity: 0;
    }
    .slide-leave-to {
        transform: translateX(-24px);
        opacity: 0;
    }

    /* 布局切换过渡：对应 layoutTransition.name = 'layout' */
    .layout-enter-active,
    .layout-leave-active {
        transition: opacity 0.15s ease;
    }
    .layout-enter-from,
    .layout-leave-to {
        opacity: 0;
    }
</style>

运行方式：在 http://localhost:3000/ 、/notes、/login 之间来回导航，观察 page / slide / layout 三组过渡效果。

最佳实践 ​

  1. 布局里永远记得写 <slot />：这是「页面一片空白」最常见的根因，每个布局文件都先检查出口。
  2. 全局过渡放 nuxt.config.ts，个性过渡放 definePageMeta：职责分层，避免在每个页面重复配置同样的过渡。
  3. mode: 'out-in' 作为默认选择：先出后进，避免新旧页面同屏互相撑破布局。
  4. 过渡时长控制在 150~300ms：再长就会显得拖沓，并放大低端设备上的卡顿感。
  5. 需要参数变化也触发过渡时，显式设置 :page-key：否则 /notes/1 → /notes/2 既没有过渡，页面数据也不会重建。
  6. keepalive 只给真正需要的页面：缓存实例占内存，用 include / max 限制缓存范围。

常见问题 ​

Q：页面完全不渲染，布局本身也不报错？ ​

A：九成是布局里漏了 <slot />。布局是页面的容器，没有出口，页面内容就被静默丢弃了。

Q：配置了 pageTransition 却看不到动效？ ​

A：按顺序排查：① 全局过渡需配置 nuxt.config.ts 的 app.pageTransition，单页过渡需 definePageMeta；② CSS 类名前缀必须与 name 完全一致；③ 路由变化是否真的改变了 page-key（仅参数变化默认不触发）。

Q：从 /notes/1 跳到 /notes/2，过渡和数据都没更新？ ​

A：同一条路由记录仅参数变化时，Nuxt 默认复用页面组件实例。给 NuxtPage 设置 :page-key="(route) => route.fullPath"，即可强制按路径重建并触发过渡。

Q：如何根据登录状态在运行期切换布局？ ​

A：使用 <NuxtLayout :name="isAdmin ? 'admin' : 'default'">，name 的优先级高于页面 definePageMeta 中的声明；切换时配合 layoutTransition 还能带上过渡动画。

小结 ​

  • app/layouts/ 即布局，default.vue 为默认布局；<slot /> 是页面出口，必不可少。
  • 页面用 definePageMeta({ layout }) 选择布局；<NuxtLayout :name> 可在运行期动态覆盖。
  • pageTransition / layoutTransition + 同名 CSS 过渡类实现转场，mode: 'out-in' 最稳妥。
  • page-key 决定页面重建与过渡触发时机；keepalive 缓存页面实例做状态保活。

自测题 ​

1. 为什么 `/notes/1 → /notes/2` 默认不触发页面过渡？如何让它触发？

page-key 默认与路由记录绑定，仅参数变化时 key 不变，组件被复用。设置 :page-key="(route) => route.fullPath" 即可按完整路径重建页面并触发过渡。

2. `mode: 'out-in'` 的含义与好处是什么？

旧页面先完成离场过渡、新页面再开始进场。好处是避免两个页面同屏并存造成的布局抖动、闪烁与滚动位置错乱。

3. 想让登录页不被站点的页头页脚包裹，需要哪两步？

① 新建 app/layouts/blank.vue，内部只保留 <slot />；② 在登录页中声明 definePageMeta({ layout: 'blank' })。
