# ADR-0002：按路由选择渲染与缓存策略

- 状态：Accepted
- 日期：2026-10-30
- 决策人：前端架构组 / 运维

## 背景

站点同时包含三类内容：

1. 知识文档：变化频率低，追求首屏速度与可抓取性。
2. 个性化数据：登录态、订单、实时状态，必须按请求渲染。
3. 列表与目录：允许分钟级延迟，适合增量再生。

如果全站统一 SSR，文档页会浪费服务端算力；如果全站静态化，登录与实时页面会返回过期内容。

## 决策

在 `nuxt.config.ts` 使用 `routeRules` 按路由声明策略：

```ts
routeRules: {
  '/rendering/ssg': { prerender: true }, // 构建期静态化
  '/rendering/isr': { swr: 60 },         // 60 秒后台再生
  '/admin/**': { ssr: false },           // 纯客户端
  '/security/headers': { headers: { ... } }
}
```

决策顺序：

1. 内容是否与用户身份相关？是 → SSR，禁止共享缓存。
2. 是否允许分钟级旧数据？是 → `swr` / `isr`，并设置 `s-maxage`。
3. 是否构建期可确定且更新可走重新部署？是 → `prerender`。
4. 是否纯后台工具、无 SEO 需求？是 → `ssr: false`。

## 后果

- 文档与营销页获得 CDN 命中率，个性化页面保留实时性。
- 需要在接口层同步设置 `Cache-Control`，否则页面缓存与接口缓存语义会冲突。
- 增量再生必须准备失效通道（发布钩子、管理端刷新）；否则用户可能长时间看到旧数据。
- 监控需要区分「页面缓存命中」与「接口回源」，否则 SLO 会失真。

## 备选方案

- **全站 SSR + CDN**：实现简单，但文档页成本高、TTFB 不稳定。
- **全站静态导出**：失去登录、实时与个性化能力。
- **全站 CSR**：首屏与 SEO 不可接受。
