# ADR-0001：以「模块注册表 + 路由组」组织知识站

- 状态：Accepted
- 日期：2026-10-30
- 决策人：前端架构组

## 背景

项目最初是一个笔记 CRUD 示例，页面按功能平铺，导航、SEO、上下页与侧边栏各自维护。站点要扩展为企业级知识库（20 个业务域、60+ 页面），继续平铺会导致三类问题：

1. 新增页面需要同时修改路由、菜单、首页卡片和 SEO，容易漏改。
2. 同名路由与组件分散在不同目录，难以按业务域统一权限与埋点。
3. 文档内容与可运行示例脱节，示例容易随代码演进失效。

## 决策

1. **页面使用路由组组织**：`app/pages/(domain)/domain/...`。圆括号目录只参与文件组织，不进入 URL；同域页面共享目录、测试与命名空间。
2. **模块注册表作为唯一数据源**：`shared/knowledge/modules.ts` 维护 `Module` 与 `Demo`，首页、侧边栏、面包屑、模块内导航、上一篇 / 下一篇、页面标题与错误页兜底全部从中派生。
3. **统一文档外壳**：每个页面使用 `DocPage`，由它负责标题、描述、标签、模块导航、上下页与 `useDocMeta`。
4. **服务端同域镜像**：`server/api/<domain>/` 与前端模块同名，接口、共享类型（`shared/types/`）与页面一起演进。
5. **示例必须可运行**：限流、SSE、流式 AI、订单状态机等演示调用真实 Nitro 接口，而不是静态截图。

## 后果

- 新增页面只需两步：建 `.vue` + 注册 `demos`，导航与 SEO 自动生效。
- 模块边界清晰，便于按域分配负责人、编写测试与接入权限。
- 代价是所有模块共享 `DocPage` 的视觉与 SEO 约定；需要非常规外壳时使用独立布局（如首页 `default`）。
- 组件自动导入关闭了路径前缀，文件名必须全站唯一；新增组件需遵守 `Demo` / 业务域前缀。

## 备选方案

- **集中式路由配置文件**：与 Nuxt 文件路由相悖，失去类型与约定优势。
- **每个模块独立 README 驱动页面**：需要引入 Markdown 渲染与额外依赖，且交互示例仍需 Vue 组件，收益有限。
- **单一长页面 + 锚点**：不利于按主题分享与 SEO，也削弱了模块边界。
