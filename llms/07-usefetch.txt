# 07. useFetch 与 useAsyncData

> 本章示例：`app/pages/index.vue`、`app/pages/notes/index.vue`、`app/composables/useNotes.ts`、`app/pages/playground.vue`

## 概念解析

`useFetch` 是 Nuxt 数据获取的门面。SSR 场景下它在**服务端**执行请求，结果随 HTML 一起序列化进 payload（`window.__NUXT__`），客户端水合时命中 payload、**不再重复发请求**——这就是「服务端取数 → payload 序列化 → 客户端水合复用」的完整链路。相比在 `onMounted` 里发请求，它消灭了二次请求与加载闪烁，还让首屏 HTML 自带数据、对 SEO 友好。

从关系上看，`useFetch` 是 `useAsyncData` + `$fetch` 的语法糖：`useFetch('/api/notes')` 约等于 `useAsyncData(key, () => $fetch('/api/notes'))`。当数据源不是 HTTP（本地计算、存储读取、多个请求组合）时，就该直接使用 `useAsyncData`、自己写 handler。两者返回值一致：`{ data, status, error, refresh, execute, clear }`，其中 `status` 取 `'idle' | 'pending' | 'success' | 'error'`，模板里用它驱动加载态；`refresh` / `execute` 重新执行，`clear` 清空数据回到初始态。

两个 Nuxt 4 的关键行为务必记住：其一，**同 key 自动共享**——`useFetch` 会根据 URL 与选项自动推导 key，`useAsyncData` 使用显式 key；任何地方用同一个 key 调用，拿到的都是同一份 `data`，不会重复请求（配合 `useNuxtData(key)` 还能只读这份共享缓存）。其二，**`data` 默认是 `shallowRef`**：嵌套属性的变更不会触发视图更新，需要深度响应时传 `deep: true`，但更推荐整体替换对象。

常用选项一览：`server`（false 则仅客户端执行）、`lazy`（不阻塞路由导航，对应别名 `useLazyFetch`）、`immediate`（false 时靠 `execute()` 手动触发）、`watch`（监听响应式源自动重取，传 `false` 关闭自动监听）、`transform` / `pick`（裁剪返回数据，减小 payload 体积）、`key`（自定义缓存 key）、`getCachedData`（自定义缓存命中逻辑）、`dedupe`（并发的相同请求 `'cancel'` 或 `'defer'`）、`default`（data 为空时的占位初始值）。

## 典型应用场景

- **SSR 列表页**：首页 `useFetch('/api/notes')`，服务端渲染即带数据，水合不重复请求。
- **响应式搜索**：`query` 传 computed，URL 上 `?q=` 变化即自动重新请求。
- **跨页面共享数据**：把请求封装进 composable（`useNotes`），列表页与详情页按 key 共享缓存。
- **懒加载次要数据**：`useLazyFetch` 不阻塞路由切换，适合「最新动态」类非关键模块。
- **非 HTTP 数据源**：`useAsyncData` + `Promise.all` 组合多个请求，或包裹任意异步逻辑。

## 完整代码示例

```vue
<!-- 文件: app/pages/index.vue -->
<script setup lang="ts">
    import type { Note } from '#shared/types/note'

    // SSR：服务端先取数并序列化进 payload，客户端水合时直接复用
    const { data: notes, status, error, refresh } = await useFetch<Note[]>('/api/notes')
</script>

<template>
    <main>
        <h1>Nuxt LearnHub 学习笔记</h1>
        <p v-if="status === 'pending'">加载中…</p>
        <p v-else-if="error">加载失败：{{ error.statusMessage ?? error.message }}</p>
        <div v-else class="note-grid">
            <NoteCard v-for="note in notes ?? []" :key="note.id" :note="note" />
        </div>
        <button type="button" @click="refresh()">重新加载</button>
    </main>
</template>
```
> 运行方式：`cd app && npm install && npm run dev`，访问 `http://localhost:3000/` ；在 DevTools Network 面板可观察到水合阶段没有重复的 `/api/notes` 请求。

```vue
<!-- 文件: app/pages/notes/index.vue -->
<script setup lang="ts">
    import type { Note } from '#shared/types/note'

    const route = useRoute()
    // 把 URL 上的 ?q= 作为搜索词；q 是 computed，变化即驱动重新请求
    const q = computed(() => (route.query.q as string) || '')

    const { data: notes, status } = await useFetch<Note[]>('/api/notes', {
        query: { q }  // query 选项接受 ref/computed，无需手写 watch
    })

    function onInput(e: Event) {
        // 只改 URL：query 变化 → computed 更新 → useFetch 自动重取
        navigateTo({ query: { q: (e.target as HTMLInputElement).value } })
    }
</script>

<template>
    <main>
        <input :value="q" placeholder="搜索笔记…" @input="onInput" />
        <p v-if="status === 'pending'">搜索中…</p>
        <NoteCard v-for="n in notes ?? []" :key="n.id" :note="n" />
    </main>
</template>
```
> 运行方式：访问 `http://localhost:3000/notes?q=nuxt` ，在输入框中输入关键字，URL 与列表会联动更新。

```ts
// 文件: app/composables/useNotes.ts
import type { Note } from '#shared/types/note'

// 列表：固定 key，跨页面/组件共享同一份数据
export function useNotes() {
    return useFetch<Note[]>('/api/notes', {
        key: 'notes-list',
        // 命中 payload/静态缓存时不再发请求（例如从详情页返回列表页）
        getCachedData: (key, nuxtApp) => nuxtApp.payload.data[key] ?? nuxtApp.static.data[key]
    })
}

// 详情：URL 不同则自动推导的 key 不同，一般无需手动指定
export function useNote(id: number) {
    return useFetch<Note>(`/api/notes/${id}`)
}
```
> 运行方式：该 composable 被首页与 `app/pages/notes/[id].vue` 复用，在 `http://localhost:3000/` 与 `http://localhost:3000/notes/1` 间切换可观察缓存共享。

```vue
<!-- 文件: app/pages/playground.vue -->
<script setup lang="ts">
    import type { Note } from '#shared/types/note'

    // useLazyFetch：lazy: true 的别名，不阻塞路由切换，因此不加 await
    const { data: latest, status: lazyStatus } = useLazyFetch<Note[]>('/api/notes', {
        query: { limit: 3 }
    })

    // useAsyncData：handler 是任意异步函数，这里用 Promise.all 组合两个请求
    const { data: dashboard, status: dashStatus } = await useAsyncData('playground-dashboard', async () => {
        const [notes, first] = await Promise.all([
            $fetch<Note[]>('/api/notes'),
            $fetch<Note>('/api/notes/1')
        ])
        return { total: notes.length, firstTitle: first.title }
    })
</script>

<template>
    <main>
        <section>
            <h2>最新笔记（懒加载）</h2>
            <p v-if="lazyStatus === 'pending'">加载中…</p>
            <NoteCard v-for="n in latest ?? []" :key="n.id" :note="n" compact />
        </section>
        <section>
            <h2>组合请求</h2>
            <p v-if="dashStatus === 'success'">
                共 {{ dashboard?.total }} 篇，首篇：{{ dashboard?.firstTitle }}
            </p>
        </section>
    </main>
</template>
```
> 运行方式：访问 `http://localhost:3000/playground` ，对比懒加载区块与组合请求区块的渲染时序。

## 最佳实践

1. **请求统一封装进 composable，key 规则集中管理**：避免散落各处的 `useFetch` 各自为政，共享缓存也依赖 key 对齐。
2. **大列表用 `pick` / `transform` 裁剪字段**：payload 会随 HTML 下发，裁剪直接减少传输体积与水合成本。
3. **非关键数据用 `lazy` 系列**：不阻塞导航与首屏渲染，配合 `status === 'pending'` 渲染骨架屏。
4. **优先「响应式 query」而非手写 `watch`**：`query` / `params` 传 ref/computed 语义更清晰，Nuxt 会自动去重并取消过期请求。
5. **用 `getCachedData` 复用 payload**：返回上一页等场景直接命中缓存，体验和流量双赢。
6. **用 `default: () => []` 提供占位初值**：模板里少写一层 `v-if="data"`，代码更平直。

## 常见问题

### Q：为什么 `useFetch` 在客户端水合时没有再发一次请求？
A：服务端取到的数据已序列化进 payload 随 HTML 下发，客户端水合时用同一 key 命中 payload 直接复用。这正是它区别于「mounted 里 fetch」的核心价值。

### Q：两个组件同时调用同一个 `useFetch`，会请求两次吗？
A：不会。key 相同的调用共享同一份异步状态与数据（Nuxt 4 行为）；使用 `useAsyncData` 时记得显式传相同的 `key`。

### Q：修改 `data.value` 的嵌套属性，视图为什么不更新？
A：Nuxt 4 中 `data` 默认是 `shallowRef`，只追踪顶层引用的替换。要么整体赋一个新对象，要么在选项里传 `deep: true`。

### Q：`watch` 选项和响应式 `query` 有什么区别？
A：`query` / `params` 传 ref 时是「参数驱动」——参数变就重取；`watch` 用于监听与请求参数无关的响应式源（如全局筛选状态）；传 `watch: false` 则可完全关闭自动重取，只手动 `execute()`。

## 小结

- `useFetch` = `useAsyncData` + `$fetch`；SSR 取数经 payload 水合，客户端不重复请求。
- 返回 `{ data, status, error, refresh, execute, clear }`，用 `status` 驱动加载态与错误态。
- Nuxt 4：同 key 自动共享数据、`data` 默认 `shallowRef`（可用 `deep: true` 还原）。
- 核心选项 `server / lazy / immediate / watch / transform / pick / key / getCachedData / dedupe / default`；响应式 `query` 传 ref 即自动重取。
- 非 HTTP 或组合请求场景手写 `useAsyncData`；`useLazyFetch` / `useLazyAsyncData` 是 `lazy: true` 的别名。

<summary><b>1. `useFetch('/api/notes')` 与 `useAsyncData('notes', () =&gt; $fetch('/api/notes'))` 是什么关系？</b></summary>

前者是后者的语法糖：`useFetch` 自动根据 URL 与选项推导 key，并内置 `$fetch` 作为 handler；需要自定义 key、非 HTTP 数据源或组合请求时用 `useAsyncData`。

</details>

<details>
<summary><b>2. 希望某数据仅客户端加载、且不阻塞从其他页面跳转过来，应如何配置？</b></summary>

传 `{ server: false, lazy: true }`（或 `useLazyFetch` 加 `server: false`）：服务端不执行该请求，导航不被阻塞，数据在客户端异步补齐。

</details>

<details>
<summary><b>3. 为什么建议对返回大对象的 `useFetch` 使用 `pick` 或 `transform`？</b></summary>

返回数据会序列化进 payload 随 HTML 下发并在客户端水合。裁剪掉模板用不到的字段，可同时减小网络传输体积与水合时的反序列化开销。

</details>
