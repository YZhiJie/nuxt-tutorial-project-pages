# 04. 导航与路由中间件

> 本章示例：`app/components/AppHeader.vue`、`app/pages/login.vue`、`app/middleware/auth.ts`、`app/middleware/logger.global.ts`
> 运行方式：`cd app && npm install && npm run dev`，未登录访问 `http://localhost:3000/dashboard` 会被重定向到 /login

## 概念解析

模板内导航用 `<NuxtLink>`：它是 vue-router `<RouterLink>` 的增强版。传入站内路径时会智能预取（默认链接进入视口即预取对应页面的 chunk 与数据），跳转几乎无感；传入 `http(s)://` 绝对地址时会渲染成普通 `<a>` 标签并自动带上 `rel="noopener noreferrer"`，也可用 `external` 显式声明。当前路由与链接匹配时会自动加上 `router-link-active` 类（精确匹配加 `router-link-exact-active`），用 `active-class` / `exact-active-class` 可改名，做导航高亮零成本。

编程式导航用 `navigateTo`：它在 setup、事件回调与中间件中都可用，SSR 时会转成真实的 HTTP 重定向。常用选项：`{ external: true }` 跳外部站点；`{ redirectCode: 301 }` 在服务端重定向时指定状态码（默认 302），老链接迁移就靠它；`{ replace: true }` 用 replace 而非 push，适合登录成功这类「不留后路」的跳转。注意在中间件中应 `return navigateTo(...)` 而不是裸调用，让 Nuxt 接管后续流程。

路由中间件分三种：内联中间件直接把函数写进页面的 `definePageMeta({ middleware: [...] })` 数组，适合一次性逻辑；具名中间件放在 `app/middleware/` 下（如 `auth.ts`），页面用 `middleware: 'auth'` 按文件名引用，可跨页面复用；全局中间件以 `.global.ts` 结尾（如 `logger.global.ts`），无需声明，每次路由切换都会执行。中间件统一用 `defineNuxtRouteMiddleware((to, from) => ...)` 定义，返回值决定去向：什么都不返回（返回 `undefined`）表示放行；返回 `navigateTo(...)` 重定向；返回 `abortNavigation()` 中止导航（可携带错误对象展示错误页）。

执行顺序上，全局中间件最先跑（多个全局中间件按文件名排序），随后是页面 `definePageMeta` 中的 `middleware` 数组，严格按数组声明顺序执行——因此把鉴权放在数组前面，后面的中间件才能拿到登录态。另外，插件等动态场景可用 `addRouteMiddleware('name', handler, { global: true })` 在运行时注册中间件，适合按功能开关动态注入守卫，属于进阶用法，知道有它即可。

## 典型应用场景

- **登录守卫**：`auth` 具名中间件检查会话 Cookie，未登录 `navigateTo('/login')`，挂在 `dashboard` 等受保护页面。
- **全局埋点/日志**：`logger.global.ts` 记录每次路由切换的 `to.fullPath`，统一采集访问轨迹。
- **老链接迁移**：中间件里对旧路径 `return navigateTo('/new-path', { redirectCode: 301 })`，SEO 权重平滑转移。
- **导航栏高亮**：`NuxtLink` 的 active 类配合 CSS，无需手写路由比对逻辑。
- **外链安全打开**：`NuxtLink` 指向外部地址时自动补全 `rel`，杜绝 `window.opener` 风险。

## 完整代码示例

```vue
<!-- 文件: app/components/AppHeader.vue -->
<script setup lang="ts">
// 组件位于 app/components/，会被自动导入到任意页面或布局
const route = useRoute()
</script>

<template>
    <header>
        <nav>
            <!-- 站内链接：进入视口即预取，激活时自动带 router-link-active -->
            <NuxtLink to="/">首页</NuxtLink>
            <NuxtLink to="/notes">笔记</NuxtLink>
            <NuxtLink to="/about">关于</NuxtLink>
            <NuxtLink to="/dashboard">控制台</NuxtLink>
            <!-- 站外链接：渲染为普通 a 标签并自动补 rel -->
            <NuxtLink to="https://nuxt.com" target="_blank">Nuxt 官网</NuxtLink>
        </nav>
        <p>当前路径：{{ route.fullPath }}</p>
    </header>
</template>

<style scoped>
/* 当前页面对应的链接高亮 */
.router-link-active {
    color: #00dc82;
    font-weight: 600;
}
</style>
```

> 运行方式：`npm run dev` 后访问 `http://localhost:3000/` ，点击导航切换页面，可观察激活高亮与「当前路径」的变化。

```vue
<!-- 文件: app/pages/login.vue -->
<script setup lang="ts">
definePageMeta({
    layout: 'blank'    // 登录页不使用默认布局
})

const username = ref('')
const password = ref('')
const errorMsg = ref('')

async function onSubmit() {
    errorMsg.value = ''
    try {
        // 演示账号 demo / nuxt1234，由 server/api/auth/login 校验并种 session Cookie
        await $fetch('/api/auth/login', {
            method: 'POST',
            body: { username: username.value, password: password.value }
        })
        // 登录成功：replace 跳转，避免用户点「后退」又回到登录页
        await navigateTo('/dashboard', { replace: true })
    } catch (e: any) {
        errorMsg.value = e?.data?.statusMessage ?? '登录失败'
    }
}

// 其他常见写法：
// await navigateTo('https://nuxt.com', { external: true })   // 跳外部站点
// return navigateTo('/notes', { redirectCode: 301 })         // 服务端 301 重定向（中间件中需 return）
</script>

<template>
    <form @submit.prevent="onSubmit">
        <input v-model="username" placeholder="用户名" autocomplete="username" />
        <input v-model="password" type="password" placeholder="密码" autocomplete="current-password" />
        <button type="submit">登录</button>
        <p v-if="errorMsg">{{ errorMsg }}</p>
    </form>
</template>
```

> 运行方式：访问 `http://localhost:3000/login` ，用 `demo / nuxt1234` 登录后跳转 /dashboard，浏览器后退键不会回到登录页。

```ts
// 文件: app/middleware/auth.ts
// 具名中间件：在 app/pages/dashboard.vue 中通过
// definePageMeta({ middleware: 'auth' }) 挂载
export default defineNuxtRouteMiddleware((to, from) => {
    // server/api/auth/login 登录成功时会种下 session Cookie
    const session = useCookie('session')

    if (!session.value) {
        // 未登录：重定向到登录页，并带上回跳地址
        return navigateTo({
            path: '/login',
            query: { redirect: to.fullPath }
        })
    }
    // 不返回任何值 = 放行
})
```

> 运行方式：未登录状态直接访问 `http://localhost:3000/dashboard` ，会被重定向到 `/login?redirect=%2Fdashboard`。

```ts
// 文件: app/middleware/logger.global.ts
// 全局中间件：文件名以 .global.ts 结尾，所有路由切换都会经过
export default defineNuxtRouteMiddleware((to, from) => {
    if (import.meta.client) {
        // 仅客户端记录，避免 SSR 阶段重复输出
        console.log(`[route] ${from.fullPath} -> ${to.fullPath}`)
    }
    // 不返回值即放行；全局中间件按文件名排序、先于具名中间件执行
})
```

> 运行方式：`npm run dev` 后打开浏览器控制台，在站内任意导航即可看到 `[route]` 日志。

## 最佳实践

- **模板用 `NuxtLink`、脚本用 `navigateTo`**：两者都对 SSR 友好；不要在 setup 里直接 `useRouter().push`，避免丢失服务端导航语义。
- **中间件里跳转必须 `return`**：`return navigateTo(...)` 或 `return abortNavigation(...)`；只调用不返回会导致导航继续执行，出现「重定向后原页面仍渲染」的怪象。
- **鉴权放具名中间件、日志放全局中间件**：可复用逻辑做成 `middleware/auth.ts`，横切关注点用 `*.global.ts`，一次性逻辑才用内联中间件。
- **留意执行顺序**：全局按文件名排序先跑，页面数组按声明序后跑；依赖登录态的中间件要排在 `auth` 之后。
- **外链交给 `NuxtLink` 自动处理**：绝对地址自动渲染 `<a>` 并补 `rel`，不要手写 `<a href>` 外链又忘了安全属性。

## 常见问题

### Q：`navigateTo` 跳外部网站为什么不生效？
A：外部地址必须加 `{ external: true }`，例如 `navigateTo('https://nuxt.com', { external: true })`；不加时会被当作站内路径处理。模板内则直接 `<NuxtLink to="https://...">` 即可。

### Q：中间件里写了 `navigateTo('/login')` 但目标页面还是闪了一下？
A：大概率是没有 `return`。中间件必须用返回值告知 Nuxt 导航结果，应写成 `return navigateTo('/login')`。

### Q：`abortNavigation` 和 `navigateTo` 怎么选？
A：要「换个地方去」用 `navigateTo`；要「这次导航作废」用 `abortNavigation()`，它可携带错误对象，如 `abortNavigation(createError({ statusCode: 403 }))`，直接展示错误页。

### Q：如何在插件里按条件注册全局中间件？
A：用 `addRouteMiddleware('my-guard', handler, { global: true })`，可在 `app/plugins/` 中根据运行时配置动态注册，无需落盘中间件文件；不加 `global` 则注册为具名中间件供页面引用。

## 小结

- `NuxtLink` 负责模板导航：站内自动预取与 active 类，站外自动渲染安全 `<a>`。
- `navigateTo` 负责编程式导航：`external` 跳外链、`redirectCode` 定状态码、`replace` 不留历史。
- 三种中间件：内联（页面数组）、具名（`app/middleware/*.ts`）、全局（`*.global.ts`）。
- `defineNuxtRouteMiddleware` 返回值三态：不返回放行、`navigateTo` 重定向、`abortNavigation` 中止。
- 执行顺序：全局按文件名 → 页面数组按声明序；动态注册用 `addRouteMiddleware`。

`auth.ts` 是具名中间件，需要页面在 `definePageMeta({ middleware: 'auth' })` 中显式引用才生效；`logger.global.ts` 以 `.global.ts` 结尾，无需声明，对每次路由切换自动执行。

<details>
<summary><b>2. 中间件里直接调用 `navigateTo('/login')`（不加 `return`）会有什么问题？</b></summary>

导航不会被终止，重定向发起后原目标页面仍会继续渲染/取数，出现闪烁或重复请求。正确写法是 `return navigateTo('/login')`，把结果交给 Nuxt 处理。

</details>

<details>
<summary><b>3. 旧地址 `/old-notes` 要永久迁移到 `/notes`，在中间件里怎么写对 SEO 最友好？</b></summary>

`return navigateTo('/notes', { redirectCode: 301 })`。服务端渲染时会返回真实的 301 响应，搜索引擎据此把权重转移到新地址；默认的 302 只是临时重定向。

</details>
