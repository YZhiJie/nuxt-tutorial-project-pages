# 01. Nuxt 4 全景认知

> 本章示例：`app/nuxt.config.ts`、`shared/types/note.ts`、`app/pages/index.vue`

## 概念解析

Nuxt 是构建在 Vue 3 之上的全栈应用框架：它在 Vue 的视图层能力之上，内置了文件路由、数据获取、服务端渲染、服务端 API（由 Nitro 引擎驱动）等一整套开箱即用的能力。Nuxt 的设计哲学是「约定优于配置」——目录结构即配置：把文件放进 `app/pages/` 就有了路由，把组件放进 `app/components/` 就能自动导入，开发者可以把精力集中在业务本身。

渲染模式是理解 Nuxt 的第一把钥匙。Nuxt 支持完整的渲染谱系：SSR（服务端渲染，每个请求在服务器生成 HTML，兼顾 SEO 与动态内容）、SSG（静态站点生成，构建时产出纯静态 HTML，适合内容稳定的站点）、CSR（客户端渲染，与传统 Vue SPA 一致），以及 Nuxt 独门的混合渲染（Hybrid Rendering）——通过 `routeRules` 按路由粒度决定每条路径用哪种模式，例如营销页走 SSR/预渲染、后台管理走纯 CSR。

从 Nuxt 3 升级到 Nuxt 4，最值得注意的变化有四点：一是源码目录默认迁入 `app/`（`app.vue`、`pages/`、`components/` 等都位于其下），与服务端代码、公共配置的边界更清晰；二是 `useFetch` / `useAsyncData` 使用相同 key 时会自动共享数据，跨组件重复请求成为历史；三是数据请求的 `data` 默认值改为 `shallowRef`，大型响应的性能更好；四是 `nuxt.config.ts` 中的 `compatibilityDate` 变为必填，用于锁定 Nitro 等平台行为，避免未来升级时出现意外行为变更。

生态方面有三件利器：Nuxt Modules（如 `@pinia/nuxt`）让功能扩展一行配置即可接入；Nuxt DevTools 内置于开发服务器，可视化查看页面、组件、composables 与请求；Nitro 服务端引擎则让同一份代码能构建到 Node、静态托管、Serverless 与边缘运行时。什么时候选 Nuxt？当你需要 SEO、首屏性能、全栈一体或团队约定化开发时，它是 Vue 生态的首选；如果只是做一个纯内部、不需要 SEO 的轻量 SPA，或团队并非 Vue 技术栈，直接用 Vite + Vue 反而更轻。

## 典型应用场景

- **内容驱动型网站**：博客、文档站、营销页依赖 SEO 与首屏速度，SSR/SSG 直接命中痛点。
- **全栈应用**：`server/api` 写接口、`app/pages` 写页面，一个仓库完成前后端，本教程的 LearnHub 示例即是如此。
- **静态站点与文档**：`nuxi generate` 产出纯静态文件，可部署到任何静态托管，成本极低。
- **混合渲染的企业系统**：对外页面 SSR 保证收录，`/admin/**` 关闭 SSR 走纯客户端，两端体验兼顾。
- **统一团队工程化**：约定式目录 + 自动导入 + DevTools，减少项目之间的心智切换成本。

## 完整代码示例

```ts
// 文件: app/nuxt.config.ts
export default defineNuxtConfig({
    modules: ['@pinia/nuxt'],    // 通过模块生态接入 Pinia
    runtimeConfig: {
        public: {
            siteName: 'Nuxt LearnHub'    // 暴露给客户端的公共配置
        }
    },
    routeRules: {
        '/admin/**': { ssr: false }    // 混合渲染：后台路径关闭 SSR，走纯客户端渲染
    },
    compatibilityDate: '2025-07-15'    // Nuxt 4 必填，锁定 Nitro 行为
})
```

> 运行方式：`cd app && npm install && npm run dev`，访问 `http://localhost:3000/admin` 可看到客户端渲染的管理页，其余页面仍为服务端渲染。

```ts
// 文件: shared/types/note.ts
// 前后端共享的类型定义，app 与 server 两侧均可引用
export interface Note {
    id: number
    title: string
    excerpt: string
    content: string
    tags: string[]
    createdAt: string
}
```

> 运行方式：无需单独运行，该类型在页面、组件与 `server/api` 中通过 `import type { Note } from '#shared/types/note'` 引用。

```vue
<!-- 文件: app/pages/index.vue -->
<script setup lang="ts">
import type { Note } from '#shared/types/note'

// useFetch 自动完成 SSR 取数与水合；相同 key 的调用会自动共享数据（Nuxt 4 行为）
const { data: notes, pending, error } = await useFetch<Note[]>('/api/notes')
</script>

<template>
    <main>
        <h1>学习笔记</h1>
        <p v-if="pending">加载中……</p>
        <p v-else-if="error">加载失败：{{ error.message }}</p>
        <!-- NoteCard 位于 app/components/，自动导入无需 import -->
        <NoteCard v-for="note in notes" :key="note.id" :note="note" />
    </main>
</template>
```

> 运行方式：`npm run dev` 后访问 `http://localhost:3000/` ，首页 HTML 在服务端渲染时已包含笔记列表。

```vue
<!-- 文件: app/components/NoteCard.vue -->
<script setup lang="ts">
import type { Note } from '#shared/types/note'

// 组件 props 直接使用 shared/ 中的共享类型，前后端契约一致
defineProps<{ note: Note }>()
</script>

<template>
    <article>
        <h3>{{ note.title }}</h3>
        <p>{{ note.excerpt }}</p>
        <!-- formatDate 来自 app/utils/format.ts，自动导入无需 import -->
        <p>发布于：{{ formatDate(note.createdAt) }}</p>
    </article>
</template>
```

> 运行方式：该组件被 `app/pages/index.vue` 自动导入使用（无需注册），访问 `http://localhost:3000/` 即可看到渲染结果。

## 最佳实践

- **默认 SSR，按需降级**：先用 SSR 获得 SEO 与首屏优势，再对纯交互页面用 `routeRules` 关闭 SSR，而不是全站一刀切。
- **公共类型放进 `shared/`**：`shared/types` 与 `shared/utils` 被 app 与 server 两侧共享，接口契约一处定义、处处复用。
- **升级前先对齐 `compatibilityDate`**：它决定 Nitro 的行为基线，团队内保持一致可减少环境差异带来的怪问题。
- **优先使用官方模块**：Pinia、Tailwind、图片优化等都有维护良好的 Nuxt Module，比手动接入省时且少踩坑。
- **关注 data 的浅响应特性**：Nuxt 4 中 `data` 默认是 `shallowRef`，确需深层响应时再显式传 `{ deep: true }`，不要盲目沿用旧写法。

## 常见问题

### Q：Nuxt 4 必须使用 `app/` 目录吗？老项目迁上来会不会爆？
A：`app/` 是 Nuxt 4 的默认源码目录，但框架仍兼容 Nuxt 3 的旧目录结构，按官方迁移指南逐步调整即可，不会强制一次性搬完。

### Q：SSR 和 SSG 怎么选？
A：内容频繁变化或千人千面选 SSR；内容在构建时就能确定、追求极低托管成本选 SSG（`nuxi generate`）。两者也可用 `routeRules` 混用，例如 `/` 预渲染、`/dashboard` 保持 SSR。

### Q：`compatibilityDate` 填什么？可以不填吗？
A：Nuxt 4 中必填。一般填写你开始使用当前 Nuxt 版本的日期（如 `'2025-07-15'`），它用于锁定 Nitro 预设的行为，具体日期含义以官方文档为准。

### Q：一定要用 TypeScript 吗？
A：不强制，但官方脚手架默认生成 `tsconfig.json`，composables 与 API 类型推断在 TS 下体验最好，本教程统一使用 TypeScript。

## 小结

- Nuxt 是 Vue 3 之上的全栈框架，约定优于配置，内置路由、数据获取与服务端能力。
- 渲染谱系覆盖 SSR / SSG / CSR / 混合渲染，`routeRules` 可按路由粒度切换模式。
- Nuxt 4 关键变化：`app/` 源码目录、同 key 数据自动共享、`data` 默认 `shallowRef`、`compatibilityDate` 必填。
- 生态三剑客：Nuxt Modules、Nuxt DevTools、Nitro，让扩展、调试、部署都更顺滑。
- 需要 SEO / 首屏性能 / 全栈一体时选 Nuxt；纯内部轻量 SPA 可直接用 Vite + Vue。
